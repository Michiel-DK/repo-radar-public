## The headline finding from day 2

**Zero newcomers. Same 77 repos as yesterday.**

GitHub Trending's "daily" tab is more sticky than it looks — every single slug in today's snapshot was also there yesterday across our 5 trending tabs (overall + Python + TS + Rust + Go). Two implications:

1. **The "daily" window is a misnomer.** The algorithm clearly uses a multi-day decay (probably 3-7 days). One snapshot a day is fine for spotting *velocity changes within the trending set*, but if we want to catch genuine newcomers as they enter, we'd need to add either (a) a star-velocity poll from the GitHub Search API independent of the trending page, or (b) a more frequent scrape (every 6h).
2. **Persistence is a strong quality signal.** Anything that survives ≥3 days here is meaningfully different from a one-day spike. Tomorrow we'll start flagging persisters; by day 4 the rolling 30d signal becomes useful.
