## What it actually is

A curated "agency" of named, personality-driven specialist sub-agents — each with a defined role, working process, and expected deliverables — packaged so you can drop them into a coding agent and delegate whole workstreams (frontend, community, QA/"reality checkers", etc.). It's the maximal expression of the *named-loadout* pattern: not a format, a staffed team. Substrate is shell + markdown agent definitions.

## What's reusable

- pattern: **role → process → deliverable** as the schema for a sub-agent definition. Each agent isn't just a prompt; it declares what it produces. Good template for any agent registry.
- pattern: **personality as a routing/UX affordance** — memorable named agents are easier to invoke and reason about than generic "sub-agent 3."
- The curation itself — a browsable catalogue of ready delegation targets, same spirit as a `repos/` catalogue but for agents.

## Project ideas (forward-looking)

- **Agent catalogue for repo-radar work**: define named agents for the recurring roles here (digest-writer, writeup-drafter, opportunity-scorer) with explicit deliverables. Why this repo: gives the role/process/deliverable schema to copy.
- **Product agent staffing**: a matching/research product could expose a named "agency" of specialist agents to end users. Why: the packaging + personality UX is proven to land (top of board).

## What to skip

- Marketing-heavy README and app upsell; the value is the agent definitions, not the hosted app.
- "Proven deliverables" is a claim, not a benchmark — treat as inspiration for structure, not evidence of quality.

## Watch-outs

- Genuinely huge (122k stars, 20k forks) for a repo created 2025-10 — this is a mainstream-scale project, not a niche one; expect a lot of surface area and churn.
